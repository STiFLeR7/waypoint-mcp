# 2026-10-19: Waypoint 0.4 direction (plugin vs MCP)

**Question (owner):** after 0.3.0, plugin-based or a purposeful MCP?

**Decision:** both, with one product. The logbook spec and the MCP servers stay the product, portable across tools.
Per-tool plugins are thin packaging that add what the rule file can't: hooks and a one-command install. 0.4 also
brings the MCP servers to the current spec, adds two MCP prompts, lists Waypoint in the official MCP Registry, and
adds a chart view inside ChatGPT (owner's addition: "include Chart View of ChatGPT also").

**Why:**
- The rule leaks. The live chart showed 9 unlogged watches across 8 of 16 tracked projects with the rule installed
  everywhere. A Stop hook can ask once per session; a rule can only ask in advance.
- Hooks in Claude Code, Codex, Gemini CLI and Copilot CLI can now force one more turn with a reason, and their
  session-start hooks can add context. Three manifests cover four tools (Copilot and Codex read `.claude-plugin`).
- The memory/handoff tools that grew (claude-mem, Basic Memory) both ended up as an MCP core plus per-tool plugins.
  Around ten pure-MCP handoff servers sit at 0–23 stars.
- MCP 2026-07-28 removed the handshake our servers use; dual-era support keeps old and new clients working.

**Kept from 2026-10-14 (foundations):** #5 navigators are adapters, no plugin framework (plugins are packaging, not
architecture); "never invent meaning" (the hook reminds, the agent writes); never change Status or archive.

**Not doing:** AI summaries of transcripts; a plugin/extension API; more tools for the sake of it; plugins for tools
whose hooks can't force a turn (Cursor, Windsurf, Kiro, Grok); removing the rule writers.

**Measure:** unlogged watches on the chart (9 on 2026-10-19) after a week of hooks on the owner's machine.
