# Logbook rules

This folder is a Waypoint **logbook**: one Markdown file per project in `projects/`, plus a generated chart. It holds no application code. Each project's own docs are the source of truth; files here summarize and link to them.

The format is defined by Waypoint's `LOGBOOK-SPEC` (v1). In short:

- `projects/<name>.md`: header (`- Path:`, `- Status:`, `- Summary:`, `- Docs:`, `- Attention:` lines), then `## Now` (`- Done:`, `- Next:`), then `## Log` **last**, newest entry first:
  ```markdown
  ### YYYY-MM-DD — <tool id>
  - <1–3 short lines; link the repo doc with details>
  ```
- Tool ids: `claude-code`, `codex`, `chatgpt`.
- Quote every line of pasted or copied text with `> `, so it can never be read as a heading or field.
- Start a project by copying `projects/_template.md`. Don't add a log entry for work that didn't happen.
- Archive by moving the file to `projects/_archive/`. Never delete project files.
- `projects/_ignore.txt` lists folders that are not projects.
- Never change Status or archive without the user's say-so. Lifecycle: `active` → `occasional` → `paused` → `done`.
- `DASHBOARD.md` and `dashboard.json` are generated by `waypoint fix`; never edit them.
- `GLOBAL-RULES.md` is the rule every tool follows in every project. Change it only by re-running `waypoint init`/`waypoint rules`.

Status requests: run `waypoint fix --logbook .`, read `DASHBOARD.md`, lead with Needs attention and unlogged sessions, and ask before tracking or ignoring untracked folders.
